## 0. 먼저 알아야 할 것

### 대본은 `docs/SCRIPT.md`에서 고친다

이번 세션에 만든 흐름이다. 대사가 `cues.ts` 안에 흩어져 있어 한 줄 고치려면
어디 적혔는지부터 찾아야 했다.

```
1. docs/SCRIPT.md에서 글을 고치거나 <br>을 옮긴다
2. src/lib/cues.ts의 같은 줄에 옮겨 적는다
3. 글자가 바뀌었으면 음성도 다시 굽는다
   node scripts/generate-audio.mjs --only <파일명>
   (<br>만 옮겼으면 굽지 않아도 된다 — 음성에는 안 들어간다)
4. python3 scripts/dump-script.py 로 문서를 다시 뽑아 대조한다
```

`dump-script.py`는 **cues.ts를 실행하지 않고 글자만 읽는다**(정규식). TypeScript라
그냥 불러올 수 없고, 대본 뽑자고 빌드 도구를 얹을 이유가 없다.

> 줄을 나누거나 합치면 **오디오도 다시 구워야 한다.** 줄 하나가 TTS 한 조각이라
> 줄 수가 곧 사이(숨)의 개수다. 글자가 같아도 나뉜 자리가 다르면 다른 음성이다.

### `<br>`은 화면에만 쓴다

`renderBreaks()`(`src/lib/subtitleLines.ts`)가 조각으로 나눠 그린다.
`dangerouslySetInnerHTML`을 쓰지 않는다 — 대사에 든 따옴표·꺾쇠까지 태그로 읽는다.
TTS로 보낼 때는 `generate-audio.mjs`가 걷어낸다. **그냥 두면 '비알'이라고 읽는다.**

### 새 오디오를 배포하면 캐시 버전을 올려야 한다

```bash
node scripts/update-sw-version.js
```

안 올리면 **기존 기기는 옛 음성을 계속 듣는다.** 서비스워커가 캐시에서 꺼내

함께 갱신한다.

## 1. 아이폰에서 소리가 안 나던 것 — 뿌리

증상은 하나였다. **소영에게 전화가 걸리고 화면은 넘어가는데 목소리가 안 들린다.**
데스크톱에서는 늘 정상이라 재현할 수 없었다.

### 헛다리 다섯

기록해 둔다 — 같은 자리를 또 파지 않기 위해서다.

| # | 짚은 것 | 왜 아니었나 |
|---|---|---|
| 1 | 자동재생 정책 | `unlockAudio()`는 이미 첫 탭에서 돌고 있었다 |
| 2 | `startCueSoon`의 0.5초 지연 | 지연을 없애도 그대로였다 |
| 3 | 화면 준비 신호를 기다리게 | **오히려 3초가 늦어졌다.** 되돌림 |
| 4 | 음소거로 권한 따기 | iOS는 음소거 재생을 자동재생으로 본다 — **풀리지 않는다**(`79c4c6f`) |
| 5 | 오디오 컨텍스트 복구 | 효과음 문제였고 목소리와는 무관했다 |

돌파구는 사용자의 한마디였다 — **"7월 23일 정도 커밋에서는 분명 됐는데."**
그 사이 바뀐 것만 보면 됐다.

### 원인 (`e562322`)

큐마다 `new Audio()`로 **새 요소를 만들고 있었다.**

iOS의 잠금 해제는 **요소 단위다.** 한 요소를 사용자 제스처 안에서 한 번
재생하면 그 요소만 풀린다. 새로 만든 요소는 다시 잠긴 상태에서 시작한다.
그런데 전화 큐는 `setTimeout(DIAL_MS)` 안에서 시작한다 — 제스처 문맥 밖이다.
**풀리지 않은 새 요소를, 제스처가 끝난 뒤에 재생하려 한 것**이다.

```ts
let sharedAudio: HTMLAudioElement | null = null
function audioElement(): HTMLAudioElement {
  if (!sharedAudio) sharedAudio = new Audio()
  return sharedAudio
}
```

**요소는 하나만 만들어 `src`만 갈아 끼운다.** 처음 탭에서 한 번 풀리면
그 뒤로는 계속 풀린 상태다.

딸려 온 것 둘:

- 이벤트를 `addEventListener`가 아니라 **`onended`·`ontimeupdate` 속성으로** 건다.
  요소를 재사용하니 예전 큐의 리스너가 쌓인다 — 속성은 덮어써진다
- `clearResources()`는 **pause만 한다.** `src`를 비우면 iOS가 요소를 다시 잠근다

> 데스크톱에서는 이 버그가 절대 안 보인다. 크롬은 요소 단위 잠금이 없다.

### 아직 확인 못 한 것

**실기기에서 통화 목소리를 확인하지 못했다.** 코드상 원인은 분명하고 데스크톱
회귀는 없지만, 아이폰에서 실제로 들리는지는 사용자만 확인할 수 있다.

## 2. 사진과 목소리를 폰에 남기기

"미션에서 찍은 사진이 아이폰에 하나도 저장되지 않는다"는 보고에서 시작했다.
**실제로 저장된 적이 없었다.** 사진은 IndexedDB(`blobStore.ts`)에만 들어갔고,
그건 앱을 지우면 함께 사라진다.

### 웹에서 아이폰 사진첩으로 가는 길은 하나뿐

`navigator.share({ files })` — 공유 시트를 띄우고 사용자가 '이미지 저장'을
고르는 것. **웹이 직접 사진첩에 쓸 수는 없다.** 이걸 못 하는 브라우저에서는
`<a download>`로 떨어진다(`savePhoto.ts`).

- **`e90e3d5`** — 찍는 순간 저장을 제안한다. 공유 시트가 뜨는 이유를 한 줄로 안내
- **`fd0f9a5`** — 버튼을 둘로 늘리지 않았다. **'소영에게 사진 보내기' 하나가
  저장까지 겸한다.** 어차피 같은 공유 시트다 — 버튼이 둘이면 무엇이 다른지
  설명해야 하고, 설명할 만한 차이가 없다
- **`cc2c639`** — B면 녹음도 같은 규칙으로. 목소리를 남기는 미션인데 정작
  그 파일이 앱 안에만 있었다

### 사파리는 `audio/webm`을 못 만든다

`MediaRecorder`에 mimeType을 주지 않으면 브라우저 기본값이 잡히는데,
사파리는 **`audio/mp4`만** 된다. `isTypeSupported`로 골라 쓰도록 고쳤다(`59cbb24`).

## 3. PWA 업데이트 — 물어볼 때도 있고 안 물어볼 때도 있던 것

"어떤 때는 '업그레이드 하겠습니까'가 뜨고 어떤 때는 없다"가 출발점이었다.

### 경합이 있었다 (`e1e3f51` · `89fdf6f`)

`sw.js`의 `install`에서 `skipWaiting()`을 부르고 있었다. 새 워커가 스스로
넘어가 버리니 `registration.waiting`이 잡히는 순간이 **경합**이었다 —
빠르면 확인 창을 띄울 대상이 이미 사라진 뒤였다.

`install`에서 걷어내고, **갈아타는 자리를 앱을 여는 순간 한 곳으로** 모았다.

### 버전을 스스로 견준다 (`dd6c18d`)

그래도 서비스워커 생명주기에만 기대면 놓치는 경우가 남는다.
`VersionGate`가 **빌드 해시를 직접 견준다** — 번들에 박힌 `BUILD_VERSION`과
서버의 `sw.js`에 적힌 값을 비교해 다르면 한 번만 새로고침한다.

- **재생 중이면 건너뛴다**(`window.__bhPlaying`). 이야기 중간에 새로고침되면
  듣던 자리를 잃는다
- **버전을 사용자에게 보여주지 않는다.** 알 필요가 없다는 요청 — 조용히 갈아탄다
- 한 버전당 한 번만 시도한다. 실패해도 무한 새로고침에 빠지지 않는다

`scripts/update-sw-version.js`가 커밋 해시를 `buildVersion.ts`와 `sw.js`에
같이 새긴다. 관리자 설정 첫 줄에도 해시가 뜬다(`d24af55`) — 푸시한 것이
기기에 반영됐는지 눈으로 확인하는 용도다.

## 6. 쿠폰·퀴즈·말 놓기

### 쿠폰 코드에 발급 순번 (`286b405`)

코드가 `(쿠폰, uid)`로 완전히 정해져 있었다. **비에 젖어 못 읽는 코드를 다시
낼 방법이 없었다** — 같은 값이 다시 나오고, 그 값은 이미 '사용됨'일 수 있다.

```
BH1-{쿠폰}-{사용자 6자}-{순번 2자}{체크 2자}
```

순번은 32진수 2자리 = 한 쿠폰당 1,024장. **이미 발급된 코드는 그대로 살아 있다**
(사용자 요청: "만들어진 번호는 그대로 놔두고 연속번호로 계속 생성").

**`cp5` 신설** — 방하림 도자기 1,000원 할인. `B5_F`의 `ui`에 붙였다.
전 세션에 "아무도 못 받는 쿠폰"으로 적어둔 항목이 이걸로 닫혔다.

### 트랙 4 신청곡 퀴즈 (`286b405`)

라디오를 듣고 나면 **아빠가 신청한 노래 제목**을 주관식으로 묻는다(`QuizInput.tsx`).

- 기존 메모 미션은 그대로 남겼다

> 아이디에 하이픈이 안 된다 — `ID_PATTERN`이 `/^[a-zA-Z0-9_]{4,20}$/`.
> 요청은 `max-test`였으나 `max_test`로 만들었다.

확인된 것:

| | 결과 |
|---|---|
| 쿠폰 | cp1 ~ **cp5 전부 지급** |
| 조각 | frag_1 ~ frag_4 |
| 포인트 | **1,950** (메인 5×300 + 스페셜 100 + 보물줄 2×50 + 보너스 5×50) |
| 중복 적립 | 없음 (`refId` 중복 0건) |
| 사진 업로드 | 정상 (Storage → 친구들 탭) |
| 랭킹 | 정상 반영 |

## 10. 그 밖에 고친 것

- **랜딩에 "진행 중인 투어가 있습니다"가 새 사용자에게 떴다.** `phase` 기본값이
  `'intro'`라 아무것도 안 한 사람도 진행 중으로 보였다. 시작 시각과 마지막 큐가
  둘 다 없으면 감춘다
- **보이지 않는 막이 탭을 삼키던 것** — 미션 오버레이가 `interaction`이 있다는
  것만 보고 막을 깔았는데 `resume`·`bingo`는 아무것도 그리지 않는다(`null`).
  그릴 것이 있을 때만 덮는다
- **퀴즈 오답 횟수가 초기화되던 것** — `onChange`에서 `setWrong(0)`을 해서
  두 번 틀려도 힌트가 안 떴다. `wrong`과 `showWrong`으로 나눴다
- **관리자 플레이어 화면에서 미션으로 바로 들어가기** — 순서를 밟지 않고 테스트
