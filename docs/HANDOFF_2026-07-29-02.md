## §5. 다음 작업 — 상점 충당률(Coverage Rate) 정산

> 아래는 사용자가 준 명세 원문이다. 이 문서만 보고 구현할 수 있게 그대로 둔다.

### 개요

- **서비스**: 김해 봉리단길 QR 오디오 드라마 미션투어. 이용자가 코스를
  결제하고 상점 QR을 스캔하며 미션을 수행하고, 그 대가로 쿠폰과 포인트를
  받아 제휴 상점에서 쓴다
- **충당률이란**: 이용자가 제휴 상점에서 쿠폰이나 포인트를 썼을 때 생기는
  할인 금액을 운영사와 상점이 나누어 부담하는 비율. **상점이 부담하는 몫**
- **가장 중요한 원칙**: **충당률은 이용자에게 보이지 않는 백엔드 정산
  로직이다.** 이용자 화면에는 쿠폰 액면가와 포인트 잔액만 보이고, 누가 얼마를
  부담하는지는 **절대 노출하지 않는다.** 상점 관리자 화면과 운영사 정산
  화면에서만 보인다

### 혜택 체계 (둘이 같은 통화로 동작)

- **쿠폰**: 2단(1만 원) 상품 결제 시 즉시 발급되는 확정 혜택. 액면 4,500원.
  결제 1건당 1장
- **포인트**: 미션 수행으로 쌓는 누적형 보조 리워드. 1p = 1원
- 둘 다 제휴 상점 결제 시 금액에서 차감되며, 차감된 금액에 **같은 충당률
  규칙**이 적용된다

### 포인트 적립·사용 규칙

- **적립**: 미션 칸 1개 100p, 빙고 1줄 500p(5×5, 최대 12줄), 코스 완주 200p
- **무결제 적립 허용**: 코스를 결제하지 않은 이용자도 보너스 미션만 수행해
  포인트를 적립할 수 있다. **이 경로를 막지 말 것.** 인근 거주자의 재방문을
  만드는 핵심 동선이다
- **사용 최소 문턱**: 3,000p. 미만이면 사용 불가로 처리하고, 화면에는
  "3,000p부터 사용 가능, 현재 1,800p"처럼 남은 양을 표시
- **유효기간**: 적립일로부터 6개월. **만료 배치는 일 단위로 실행**하며 적립
  건별 **FIFO**로 소멸
- 소멸 포인트는 회계상 부채로 인식하지 않는다

### 상점 등급과 충당률

| 등급 | 충당률 | 적용 조건 |
|---|---|---|
| 신규 | 0% | 가입일로부터 3개월. 이 기간 할인액은 운영사가 전액 부담 |
| 기본 협력 | 60% | 신규 기간 종료 후 기본값 |
| 프리미엄 | 85% | 프리미엄 회원(월 3만 원) 가입 상점. 노출량이 크므로 부담도 큼 |

충당률은 **상점 단위 속성**이며, 등급 변경 시점 **이후** 발생한 사용 건에만
적용된다.

### 데이터 모델 요구사항

- **`merchant`**: 상점 ID, 상호, 등급(신규/기본/프리미엄), 충당률, 가입일,
  신규 기간 종료일, 월 충당 상한액, 계약 상태
- **`reward_issue`**: 발급 ID, 이용자 ID, 종류(쿠폰/포인트), 액면 또는
  포인트, 발급 사유(결제/미션/빙고/완주), 발급일, 만료일, 사용 여부
- **`redemption`**: 사용 ID, 발급 ID, 상점 ID, 사용일시, 사용 금액,
  **적용 충당률(스냅샷)**, **상점 부담액(스냅샷)**, **운영사 부담액(스냅샷)**
- **`settlement`**: 정산 ID, 상점 ID, 정산 월, 회비, 충당액 합계, 청구 총액,
  상태

### 핵심 구현 규칙 — 스냅샷 저장

- 사용 시점의 충당률과 분담 금액을 `redemption` 레코드에 **값으로 복사해
  저장**할 것. 상점 등급이 나중에 바뀌어도 과거 정산 내역이 소급 변경되면
  안 된다
- **절대 하면 안 되는 구현**: 정산 시점에 `merchant.coverage_rate`를 조인해서
  계산하는 방식. 등급 변경 시 과거 데이터가 통째로 틀어진다

### 계산 산식

```
사용 금액     = 쿠폰 액면 또는 사용 포인트 수 (1p = 1원)
상점 부담액   = 사용 금액 × 충당률
운영사 부담액 = 사용 금액 × (1 − 충당률)
```

- 예시 1: 액면 4,500원 쿠폰, 기본 협력(60%) → 상점 2,700원, 운영사 1,800원
- 예시 2: 3,000p 사용, 프리미엄(85%) → 상점 2,550원, 운영사 450원
- 예시 3: 액면 4,500원 쿠폰, 신규(0%) → 상점 0원, 운영사 4,500원

### 월 충당 상한 (상점 보호 장치, 필수)

- 상점별 월 충당액 상한을 두고, 도달 시 그 상점에서의 쿠폰·포인트 사용을
  그 달 동안 **차단**한다
- 권장 초기값: 기본 협력 월 3만 원, 프리미엄 월 6만 원
- 상한 도달 시 이용자 화면 문구: **"이 매장은 이번 달 혜택이 마감되었습니다.
  다른 제휴 매장에서 사용해 주세요."** 상점 사정이나 충당률을 설명하지 말 것
- 소진율 80% 초과 시 상점 관리자에게 알림

### 정산 프로세스

- 주기: 월 1회, **익월 10일 마감**
- 상점 청구액 = 월 회비(기본 1만 원 / 프리미엄 3만 원) + 당월 충당액 합계
- 상점 관리자 화면에 **반드시 함께 표시**: 당월 QR 스캔 수, 당월 쿠폰·포인트
  사용 건수, 충당액, 그리고 **충당액 대비 실제 매출 유입액**.
  상점이 "얼마를 냈는가"만 보면 이탈하고, "얼마를 받았는가"를 함께 봐야
  유지된다
- 이의 제기: 마감 후 5영업일

### 회계 처리상 유의

- 상점 충당액은 **매출이 아니라 운영사 원가의 차감 항목**으로 처리.
  매출로 계상하면 재무제표가 부풀려진다
- **운영사 부담액만** 비용 계정에 계상
- 리포트 API 반환값(기간별): 총 발행 액면, 총 사용 액면, 상점 충당액 합계,
  운영사 부담액 합계, 미사용 소멸 액면, 사용률

### 관리자 설정 항목 (하드코딩 금지, 전부 설정값)

등급별 충당률 · 신규 유예 기간(개월) · 쿠폰 액면 · 포인트 문턱 · 포인트
유효기간(개월) · 미션 칸 배점 · 빙고 줄 배점 · 완주 보너스 · 상점별 월 충당
상한. **배포 없이 변경 가능해야 한다.**

### 예산 모니터링 (운영사 대시보드)

- 운영사 부담액이 당월 매출의 **3%** 를 넘으면 경고. 3%가 리워드 예산 천장
- 함께 볼 지표: 결제 1건당 평균 적립 포인트(목표 약 1,800p), 포인트
  실사용률(목표 25~30%), 무결제 적립 이용자 비율

### 착수 전 확인할 것 (지금 코드와의 간극)

- 지금 `firestore.rules`의 `shops/*`에는 등급·충당률·상한 필드가 **없다.**
  `couponUses`가 `redemption`에 가장 가깝지만 스냅샷 필드가 없다
- `adminStats.shopSettlement()`는 쿠폰 액면을 그대로 돌려주는 계산이라
  충당률 개념이 아예 없다. 여기를 갈아엎어야 한다
- **포인트를 차감하는 경로가 통째로 없다.** 쿠폰은 QR 토큰 + `couponUses` +
  규칙 검증이 있는데 포인트는 그 짝이 없다. 사용자 결정 4번("가게 입장에서
  같은 형태")을 따르면 **쿠폰 사용 경로를 포인트로 확장**하는 것이 맞다 —
  새로 만들지 말고 `shops.ts`의 `redeemCoupon()` 옆에 세울 것
- 월 배치(만료 FIFO, 정산 마감)를 돌릴 서버가 없다. Cloud Functions를 쓸지,
  관리자 화면에서 손으로 돌릴지 **먼저 정해야 한다**
