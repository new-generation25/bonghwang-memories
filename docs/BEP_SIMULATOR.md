# BEP 시뮬레이터 — 저장과 불러오기

**2026-08-03 고쳐 씀.** 주소는 **`/bep/index.html`** — 새 탭에서 연다.
`/admin`의 「📈 BEP 시뮬레이터 ↗」가 그 문이다.

> **8/3에 앱 밖으로 내보냈다.** 8/2에는 `/admin/bep`이 iframe으로 품고
> 있었는데 셋이 걸렸다 — 폭 1080px에 입력 60여 개라 폰에서 못 쓰고,
> 앱을 홈 화면에 설치해 두면 주소창 없는 앱 창으로 열려 빠져나올 길이
> 없고, `X-Frame-Options`가 같은 출처 iframe까지 막았다.
>
> **대신 서버 저장이 꺼졌다.** 토큰을 넣어주던 자리가 앱 페이지였다.
> 지금은 어느 길로 열어도 **이 브라우저에만** 남는다(아래 §1). 기기를
> 옮겨 가며 같은 시나리오를 봐야 하면 「파일로 내보내기」를 쓴다.

> **수치는 이 화면에서 직접 고친다.** 앱의 쿠폰·포인트 코드
> (`points.ts`·`coverage.ts`·`coupons.ts`)와는 아직 이어져 있지 않다.
> 시뮬레이터의 값은 재무 가정이고, 앱의 값은 참여자에게 나가는 실제
> 혜택이다. 둘을 잇는 것은 별도 작업이다(아래 「아직 안 된 것」).

---

## 1. 값이 남는 세 자리

| | 어디에 | 언제 | 기기를 옮기면 |
|---|---|---|---|
| **지금 화면** | 이 브라우저 | 값을 만질 때마다 **저절로** | 안 따라온다 |
| **이름 붙인 설정** | 이 브라우저 | 「현재 설정 저장」을 누를 때 | 안 따라온다 |
| **서버 시나리오** | Firestore | 「새로 저장」을 누를 때 | **따라온다** |

### 지금 화면 — 아무것도 안 눌러도 남는다

입력 60여 개를 손으로 맞춰 놓고 새로고침 한 번에 잃는 것이 이 화면에서
가장 아픈 사고였다. 그래서 값을 만질 때마다 화면 전체를 브라우저에
남긴다(`lm_bep_current_v1`). **저장을 누르지 않아도** F5·탭 닫기·다음 날
다시 열기에서 그대로 이어진다.

이건 이름이 없고 하나뿐이다. 여러 안을 견주려면 아래 이름 저장을 쓴다.

### 이름 붙인 설정 — 견주기 위한 것

이름을 넣고 「현재 설정 저장」을 누른다. **같은 이름이면 덮어쓴다.**

- 최대 **20개**. 넘으면 **저장이 막히고 알린다** — 예전에는 10개를 넘으면
  가장 오래된 것을 말없이 지웠다. 한 안을 다듬는 동안 한도에 닿아, 며칠 전에
  잡아둔 기준안이 사라진 줄도 모르게 된다
- 칩을 누르면 불러온다. `×`는 확인을 한 번 묻는다
- 옆 숫자는 2028.12 누적 손익 — 어느 안이 어땠는지 목록에서 바로 보인다

### 서버 시나리오 — 기기를 옮겨 다닐 때

`FIREBASE_SERVICE_ACCOUNT`가 있고 관리자로 로그인했을 때만 켜진다. 켜지면
위쪽에 「시나리오 이름」칸이 서고 로컬 슬롯은 접힌다.

**kpi는 클라이언트가 보낸 값을 쓰지 않는다.** 서버가 `runModel`로 다시
계산해 넣는다 — 화면과 모델이 갈라지면 저장된 숫자부터 틀리기 시작한다.

`params`는 `normalizeParams()`를 지난 값만 저장된다. 모르는 키는 버리고 빠진
키는 기본값으로 메우므로, 모델에 입력이 늘어도 옛 시나리오가 깨지지 않는다.

> **자격증명이 없어도 시뮬레이터는 돌아간다.** 서버 저장만 꺼지고 화면에
> "아래 로컬 저장을 쓰세요"가 뜬다. 키는 저장소에 없고 외장하드를
> 따라다니므로, 키가 없는 자리에서 화면이 안 열리면 안 된다.

## 2. 계산은 한 곳에만 — 이라고 하고 싶지만

`src/lib/bepModel.js`가 서버·검증이 보는 원본이고, `public/bep/index.html`
안에 **같은 계산의 사본**이 있다. 합치지 못한 이유는 HTML이 빌드 없이 파일
하나로도 열려야 해서다.

둘이 갈라지면 화면에서 본 숫자와 저장된 숫자가 조용히 달라진다. 그래서
대조기를 둔다 — **모델이나 화면을 고쳤으면 이걸 먼저 돌린다.**

```bash
npm run check:bep
```

여섯 시나리오(기본 / 확정 반영안 / 고정상한 / 직접충당 / 한도적용 /
상점포인트) × 28개월 × 10개 항목을 전부 대조한다. 한 칸이라도 다르면
어느 달 어느 열인지 찍어 준다.

## 3. 세션 간 공유

```
GET /api/bep/export?token=<BEP_EXPORT_TOKEN>
```

로그인 세션이 아니라 **토큰**으로 막으므로 브라우저 밖에서 URL 하나로
읽힌다. 다른 작업 세션에서 지금 값을 그대로 보게 하는 것이 시뮬레이터를
앱에 넣은 이유다.

- `BEP_EXPORT_TOKEN`이 없으면 **항상 404.** 401이 아니라 404인 것은
  일부러다 — 401은 "여기 뭔가 있다"를 알려준다
- `kpi`는 지금 모델로 다시 계산한 값, `kpiAtSave`는 저장 당시 값이다.
  둘이 다르면 그 사이 모델이 바뀐 것이라 바로 눈에 띈다

## 4. 모델에서 걸려 넘어지기 쉬운 자리

- **`cov`(상점 충당률)는 자동 모드에서 입력값이 무시된다.** `covMode = 1`이면
  쿠폰 문턱·마진율에서 계산한 값이 들어간다. 지금 조건은 100%를 여유 있게
  넘겨 포화라, 마진율을 임계 아래로 내리기 전에는 값을 바꿔도 월별 손익이
  안 움직이는 것이 정상이다
- **`gov`(정부지원금)는 손익·현금 어디에도 안 들어간다.** 들어오는 즉시
  사업비로 나가는 전제라 표시용이다. 자부담도 `ownK`(현물)는 현금 유출이 없다
- **`capMode = 1`(자동 상한)** 은 상권 침투율 상한에서 가맹점 수를 역산해
  자른다. 목표를 아무리 올려도 유동인구가 안 받치면 잘린다
- **뽑기 실물 원가(`gaN`·`gaP`·`gaC`)** 는 2026-08-02에 새로 들어왔다.
  이전 계산에는 없었으므로 옛 숫자와 비교할 때 주의한다
- **`pgRate`는 굿즈의 소비자 정가**다. 1p = 1원 원칙상 원가의 1.5~2.5배를
  넘기면 참가자 입장에서 가치 절하가 된다. 비용이 부담되면 레이트가 아니라
  적립(배점)을 낮춘다

## 5. 아직 안 된 것

- **`config/points`와 시뮬레이터 값이 각자 논다.** 앱 배점을 바꾸면
  시뮬레이터도 손으로 맞춰야 한다. 어느 쪽을 원본으로 삼을지가 먼저다
- 시나리오 **비교 뷰** — 둘을 골라 다른 입력만 표로
- 뽑기 상품표(`GACHA_PRIZES`)의 가중평균 원가를 `gaC`에 자동 반영
- 첫 시나리오를 서버에 넣기. 확정값은 `docs/bep/seed-scenario.json`에 있다

```bash
curl -X POST https://<도메인>/api/bep/scenarios \
  -H "authorization: Bearer <관리자 ID 토큰>" \
  -H "content-type: application/json" \
  -d @docs/bep/seed-scenario.json
```
