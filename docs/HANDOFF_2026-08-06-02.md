## 1. 이번 세션에 한 일

### 가게 계정 만들기가 규칙 위에서 깨져 있었다 — `3033c54`

`scripts/make-shop-accounts.mjs`가 `users/{uid}` 문서를 만들 때 `loginId`를
함께 적고 있었다. **그 칸이 있으면 `firestore.rules`가 create·update를 통째로
거부한다** — 아이디가 공개로 읽히던 구멍을 막으면서 넣은 조건이다.

```
firestore.rules  users/{userId}
  allow create: … && !('loginId' in request.resource.data);
  allow update: … && !('loginId' in request.resource.data);
```

**증상이 고약한 종류다.** Auth 계정은 만들어지고 프로필 문서 쓰기만
permission-denied로 죽는다 — 사장님은 로그인이 되는데 화면만 어긋난다.
스크립트도 계정을 세어 성공처럼 보고한다.

고친 것 둘:

- `setDoc`에서 `loginId`를 뺐다. 아이디는 이미 내부 이메일
  (`{아이디}@bonghwang.local`)에 들어 있고 그 이메일은 본인만 읽는다 —
  `auth.ts`의 `toStoredProfile`·`fromInternalEmail`이 같은 이유로 이미 빼고 있다
- `nicknameKey`가 `trim + 소문자`뿐이라 `publicMirror.ts`의 `toNicknameKey`와
  어긋나 있었다(`/` → `_` 치환이 빠졌다). 같은 헬퍼 모양으로 맞췄다

새로 만든 `scripts/make-admin-accounts.mjs`(`e7959f0`)가 이미 옳은 모양이었다 —
그쪽을 본떴다.

> **실제 가게 계정을 새로 만들어 확인하지는 않았다.** 운영 프로젝트라 시험
> 계정이 남는다. 규칙 조건과 `auth.ts`의 실제 쓰기 모양을 대조해서 고쳤다.

### 함께 짚어 둔 것 (안 고침)

`make-shop-accounts.mjs`는 admin 스크립트와 달리 —

- `nicknames/`·`rankings/` 문서를 만들지 않는다
- 이미 있는 계정(`auth/email-already-in-use` 갈래)일 때 **프로필 문서를 채우지
  않는다**. 그러니 지금까지 위 오류로 문서가 비어 있는 가게 계정이 있다면
  **다시 돌려도 채워지지 않는다**

이번 요청 범위 밖이라 손대지 않았다. §4에 남긴다.
