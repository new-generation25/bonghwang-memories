BEP 「앱에 반영」 → 화면 안 확인 창(무엇 → 무엇) → [반영한다] → 저장

링크에 실어 주므로 묻지 않는다.

- **대표 인건비는 칸을 아예 두지 않았다** — 현물로만 계상할 수 있어서,

## 2. 넘어진 자리 (같은 실수를 반복하지 않도록)

### `vercel.json`의 `builds`를 걷어내면 사이트가 통째로 내려간다

**8/4 새벽에 4분간 운영을 내렸다.** 홈·`/play`·`/track/1`·`/me`가 전부
404가 되고 `public/` 정적 파일만 나왔다. 되돌려 복구했다(`244f4bc`).

8/2에도 같은 일이 있었다(`ed53c43` → `a54c28e`). **되돌린 이유가 기록에
없어서 같은 자리를 두 번 밟았다.**

| | `builds` 있음 (지금) | `builds` 없음 |
|---|---|---|
| 사이트 | ✅ 정상 | ❌ 전부 404 |
| `/api/*` | 있음, 그러나 **500** | **아예 없음** |

`builds`가 있으면 Vercel이 레거시 빌더로 돌며 프로젝트 설정을 무시한다 —
`engines: 22.x`가 안 먹고 `firebase-admin@14`(`node >=22` 요구)가 **모듈을
불러오는 순간** 죽는다. `/api/bep/export?token=x`가 404가 아니라 500을 내는
것이 그 증거다(토큰 검사에 닿기도 전에 죽는다).

`builds`를 빼면 Vercel이 **프로젝트의 Framework Preset**을 보는데, 그게
Next.js로 안 잡혀 있어 정적 사이트로 배포된다.

> **순서가 전부다.** Vercel 대시보드에서
> `Settings → Build & Deployment → Framework Preset = Next.js`,
> `Node.js Version = 22.x`를 **먼저** 맞춘 뒤에야 `builds`를 걷어낼 수 있다.
> 반대로 하면 사이트가 내려간다. **세 번째로 같은 곳을 밟지 마라.**

### 인계에 적힌 '남은 일'을 확인 없이 믿었다

"Vercel 환경변수 둘이 없다"고 두 번 말했는데 **둘 다 들어가 있었다.**
8/2 인계의 미완 목록을 그대로 읽고 확인을 안 한 탓이다. 배포된 엔드포인트에
직접 물어보면 404(토큰 없음)·503(자격증명 없음)·401(정상)로 갈린다.

같은 식으로 COUPON_FLOW.md §6의 "혜택 사용 계측이 없다"도 **낡은 글이었다**
— `shops.ts:369`·`shops.ts:468`에서 실제로 부른다.

### `next dev`는 부모만 죽이면 자식이 포트를 쥐고 남는다

`TaskStop`으로 껐다고 믿고 새로 띄우면 EADDRINUSE로 죽고, **낡은 서버가
계속 응답한다.** 새로 만든 라우트가 404로 나와 한참 헤맸다. 포트를 쥔
프로세스를 직접 죽여야 한다.

```powershell
Get-CimInstance Win32_Process -Filter "Name='node.exe'" |
  Where-Object { $_.CommandLine -like '*bonghwang-memories*next*' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

### 사양서 코드에도 이중 충당 구멍이 있었다

`SPEC_지원사업탭.md` §2-2 스니펫이 `pool`에서 `rent`만 깎지 않는다. 임차료를
충당하는 사업이 둘이면 **같은 월세를 두 번 받는다** — 3,509만이 4,469만으로
부풀었다. 월세 천장을 「그 달 활성 사업이 신고한 값 중 최대」로 뒀다.
사업마다 적는 80만은 각자의 몫이 아니라 **같은 사무실의 같은 월세**다.
