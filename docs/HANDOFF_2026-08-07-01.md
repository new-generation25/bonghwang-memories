## 1. 이번 세션에 한 일

앱 코드는 건드리지 않았다. **`design/`이 새로 생겼다.**

### 카세트와 플레이어를 SVG로 뽑았다 — `160ac76`

일러스트로 그린 것을 앱에 넣을 수 있느냐는 물음에서 시작해, 반대로 **앱이 이미
가진 것을 벡터로 꺼내는** 일이 됐다.

```
design/cassette.svg          316×190   ← Cassette.tsx + globals.css .cassette
design/cassette-player.svg   360×276   ← intro/page.tsx + globals.css .player-shell
design/README.md
```

**트레이싱이 아니다.** 둘 다 CSS 도형이라 좌표를 그대로 옮겼다. 손으로 옮기면
틀리므로 생성 스크립트로 뽑고, dev 서버에 실제 마크업을 주입해
`getBoundingClientRect`로 재고 SVG는 `getBBox`로 재서 맞췄다 — 라벨·창·릴·하단
트랩·키 다섯 개가 **소수점 둘째 자리까지 일치**한다.

**글자 베이스라인만은 계산으로 안 됐다.** 폰트 크기 × 1.2로 잡았더니 한글 글꼴의
줄상자가 그보다 커서 9px 헤드가 2.4px, 26px 손글씨가 1.2px 어긋났다. 실측값을
박았다. 카세트가 300이 아니라 316인 것은 SIDE 배지가 `left:-13`으로 몸체 밖에
걸치기 때문이다.

**`public/`이 아니라 `design/`에 둔다.** 앱이 읽는 파일이 아니고, `public/`에
두면 빌드에 실려 나가고 `sw.js` 선캐시 목록과 어긋난다.

### 앱 실제 모습을 참고용 PNG로 남겼다 — `5cc7568`

**SVG는 그림자 28개 중 8개만 들고 있다.** 딱 떨어지는 것(나사 링·배지 그림자·키
아래 턱·상단 하이라이트)만 살렸고 **블러가 들어간 20개는 뺐다** — 벡터 도구가
SVG 필터를 잘 못 읽어서 넣으면 오히려 편집이 어려워진다.

대신 Playwright로 앱을 실제 렌더해 3배 PNG로 남겼다(`design/reference/`).
릴 회전은 멈춰 세우고 찍었다 — 기준 이미지가 매번 달라지면 안 된다.

크게 다른 두 곳 — 카세트 창의 `inset 0 2px 6px`(파인 느낌)과
`.deck-window::after`의 inset 4개. **후자가 없으면 테이프가 도어 위에 붙인
스티커처럼 평평해진다.** CSS 주석이 "뚫린 구멍으로 읽히게 하는 핵심"이라고 적어
둔 그것이다.

| 무엇 | 왜 | 어떻게 |
|---|---|---|

| `npx firebase deploy` | **권한 분류기가 막는다.** 운영 규칙을 바꾸는 명령이라 막히는 게 맞다 | 사용자가 직접 돌리거나, 설정에 Bash 권한을 연다 |

| `page.goto(networkidle)` | HMR 소켓 때문에 영영 안 끝난다 | `domcontentloaded` + `document.fonts.ready` |
| 스크래치패드의 `.mjs` | `playwright` 해석을 못 한다(패키지가 프로젝트에 있다) | 프로젝트 루트에 복사해 돌리고 지운다 |
