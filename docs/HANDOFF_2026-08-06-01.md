### 저장 체계에 구멍이 넷 있었다

지원사업 탭을 붙인 뒤 저장 경로를 훑다가 나왔다. **넷 다 계산은 맞고 오류도
없어서, 눈으로 보기 전에는 모르는 종류다.**

- **불러온 지원사업이 화면에 안 떴다.** `setAll`이 `GRANTS`를 채우고도 표를
  다시 세우지 않아, 목록은 "등록된 지원사업이 없습니다"인데 계산에는 들어가
  있었다. 화면과 값이 어긋난 채로 돈다
- **옛 형식(`subCap`)을 파일·슬롯으로 불러오면 사업비가 사라졌다.** 변환이
  모델 쪽 `normalizeParams`에만 있었다 — 서버로 불러올 때만 살아났다
- **파일에서 슬롯을 10개까지만 읽었다.** `MAX_SLOTS`는 20인데 이 자리만 옛
  값이었다. 8/2에 "넘으면 막고 알린다, 지우지 않는다"로 정한 원칙이 여기만
  안 고쳐져 있었다
- 저장 파일에 형식 번호가 없었다

### 불러오는 문을 하나로 모았다

길이 다섯이었다 — 브라우저 슬롯 · 파일 · 서버 · 새로고침 복원 · 프리셋.
다섯이 제각각 `setAll`을 부르니 검증도 다섯, 옛 형식 변환도 다섯이었고,
**그중 하나만 안 고쳐지는 일이 실제로 두 번 일어났다.**

```
다섯 갈래  →  applyScenario()  →  화면
                · 숫자 아닌 값은 버리고 기본값으로
                · 옛 단일 pool → 지원사업 목록
                · 얹기
```

**서버가 붙어도 브라우저 저장을 감추지 않는다.** 예전에는 접어 두었는데,
그러면 이 브라우저에 저장해 둔 것에 닿을 길이 없어진다. 서버가 주가 되는
것과 지난 저장을 못 보게 하는 것은 다른 일이다.

슬롯 칩에 저장 시각과 지원사업 건수를 넣었다 — `시험안 21,382,737 💰2 8/5 21:35`.
이름과 누적 손익만으로는 어느 것이 최신인지, 지원금을 넣고 잡은 안인지 뺀
안인지 구분할 수 없었다.

## 2. 운영 500 — 이번에 밝힌 것과 밝히지 못한 것

### Node 버전 가설은 틀렸다

8/2의 `ed53c43` 커밋 메시지가 *"builds가 있으면 Vercel이 레거시 빌더로 돌면서
프로젝트 설정을 무시한다. Node 버전 지정도 그래서 안 먹은 것으로 본다"* 고
적었고, 8/4-01 §2가 그것을 그대로 옮겼다. **둘 다 추측이었고, 반증됐다.**

이번에 확인한 것:

| | |
|---|---|
| Vercel 프로젝트 설정 | Framework Preset `Next.js` · Build/Output/Install **Override 전부 꺼짐** · Node **22.x** |
| `builds` 없이 미리보기 배포 | **여전히 `/api/bep/token` 500** |

설정이 이미 맞는데도 죽는다. 그러니 원인은 Node 버전도, 레거시 빌더도 아니다.

> **환경변수도 아니다.** `BEP_EXPORT_TOKEN`·`FIREBASE_SERVICE_ACCOUNT` 둘 다
> Vercel에 들어가 있다(8/4에 확인). 이것도 한 번 틀리게 말했던 자리다.

### 아직 안 본 것 — 실제 오류 문구

`/api/bep/*`는 오류를 삼키도록 짜여 있어 무엇이 터졌는지 몸통이 안 나온다.
그래서 브랜치에 **진단 라우트**를 뒀다.

```
/api/bep/diag
```

값은 안 내보내고 참/거짓과 오류 문구만 낸다 — `node`(실제 런타임 버전) ·
`serviceAccountParses` · `privateKeyLooksRight` · **`firebaseAdminImport`** ·
`bepModelImport`. `firebase-admin`을 **동적으로** 부르는 것이 핵심이다. 다른
라우트는 파일 맨 위에서 정적으로 부르므로 그 모듈이 터지면 라우트 코드가 한
줄도 안 돌고 500이 된다.

**미리보기에는 Vercel 로그인 보호가 걸려 있어 밖에서 못 찍는다** — 전부
SSO로 넘어간다. 사람이 브라우저로 열어야 한다.

> **다음 세션이 할 첫 일**: 미리보기 배포(`ee739c4`)의 주소로 `/api/bep/diag`를
> 열고 나온 JSON을 본다. `firebaseAdminImport: "failed"`면 그 오류 문구가 답이다.
> `/api/bep/diag`까지 500이면 원인이 그 모듈이 아니라 더 앞단에 있다.

### 두 번 밟은 자리 (세 번째로 밟지 마라)

`vercel.json`의 `builds`를 걷어내면 **사이트가 통째로 404가 된다** — 8/2 ·
8/4 새벽 두 번 겪었다. 다만 이번에 프로젝트 설정이 맞는 것을 확인했으므로,
**미리보기에서 홈이 뜨는지 먼저 보고** 나서만 `master`에 넣는다.
