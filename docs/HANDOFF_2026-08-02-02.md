### 시뮬레이터 저장에 구멍이 셋 있었다

목적이 "저장이 편리하고 확실할 것"이었으므로 여기를 제일 손봤다.

- **고치던 값이 새로고침에 통째로 날아갔다** → 값을 만질 때마다 저절로
  남긴다(`lm_bep_current_v1`). 저장을 누르지 않아도 이어진다
- **슬롯이 번호뿐이라 뭐가 뭔지 몰랐다** → 이름으로 저장하고, 같은 이름이면
  덮어쓴다
- **10개를 넘으면 가장 오래된 것을 말없이 지웠다** → 20개까지 두되 넘으면
  **막고 알린다.** 지우지 않는다

계산이 모델(`src/lib/bepModel.js`)과 화면(HTML 안 사본) 두 곳에 산다 —
HTML이 파일 하나로도 열려야 해서 못 합친다. 대신 대조기를 뒀다.

```bash
npm run check:bep    # 6개 시나리오 × 28개월 × 10개 항목
```

### 점빵 자리 — 이번 세션의 진짜 버그

미야상회 도착 전, *'조그만 점빵이 하나 있어'* 다음에 안 넘어간다는 제보였다.
재현해 보니 화면이 **"통화가 잠시 끊겼어요"** 를 띄우고 있었다.

`B1_WALK`은 정상적으로 끝났다. §10 재개 분기가 `lastCueCompleted`만 보고
판단하는데, 그 값은 **정상 종료에서만** 세워지므로(`cueEngine.finishCue`)

한동안 안 드러난 것은 큐들이 대개 미션을 열거나 다음 큐로 이어져서다.
**`B1_WALK`이 `next`도 미션도 없이 끝나는 첫 큐라** 8/1 대본 개정으로 이
큐가 생기면서 처음 나왔다.

지금은 끝맺음 큐를 다 들었고 그 거점을 이뤘으면 「다음 거점 · 미야상회 ·
걸어가서 QR을 찍으세요」와 지도·다시듣기를 준다. 다섯을 다 이룬 뒤에는
다음 거점을 지어내지 않는다.

## 2. 넘어진 자리 (같은 실수를 반복하지 않도록)

**"BEP 링크가 없다"는 것이 코드 문제가 아니었다.** 커밋만 하고 푸시를 안
해서 Vercel에 없었던 것이다. 로컬에서도 관리자 로그인 뒤에야 그려지는
자리라 두 겹으로 헷갈렸다. → **화면에 안 보인다는 제보를 받으면 코드보다
`git status -sb`를 먼저 본다.**

**E2E를 콜드 dev 서버에 워커 6개로 때리면 헛되이 죽는다.** `stations` 3개가
300초·420초를 넘겨 실패했는데, 데워진 서버에 워커 1개로 다시 돌리니 24초에
끝났다. `next dev`의 온디맨드 컴파일이 밀린 것이다. → **`--workers=2`,
서버를 미리 데워 둔다.**

**글꼴을 바꾸면 글자폭이 달라져 배치가 깨진다.** 감자꽃은 Nanum Pen Script
보다 훨씬 넓어서 같은 24px에서 소원이 두 줄로 깨졌다. 크기를 다시 재고
(19px / 400px↑ 21px), '아버지의 몫'을 각주 줄로 내려 자리를 벌었다.

**브라우저로 검증할 때 로그인 상태면 `tourSync`가 심은 상태를 덮는다.**
`localStorage`에 투어 상태를 심고 확인하려다 서버의 실제 진행(5/5)으로
덮여 엉뚱한 화면을 봤다. → **상태를 심어야 하는 검증은 E2E로 한다.**

**`srvUI()`가 `MAX_SLOTS` 선언보다 먼저 불려 TDZ 오류가 났다.** 시뮬레이터
HTML은 스크립트 한 덩어리라 선언 순서가 그대로 실행 순서다.
